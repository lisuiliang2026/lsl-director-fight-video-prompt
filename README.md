# 导演打斗模块 · lsl-director-fight-video-prompt

一个 Claude skill：把剧本里的一段打斗戏，写成一条可以整段复制、直接粘贴进视频模型生成的**全量提示词**。

| 项 | 现状 |
|---|---|
| 版本 | v0.2（2026-11-11），测试版 |
| 效果 | 未验证。规则和示例写齐了，还没有在本 skill 下做过生成对照，见[测试状态](#测试状态与并入路线) |
| 目标模型 | 即梦 Seedance 2.5，单段 15 秒以内 |
| 产出 | 只出文本，不生成图片和视频 |
| 和 director-video-prompt 的关系 | 独立运行，不读也不改它的文件；只在行格式上适配，测到认可以后再并入 |

skill 本体是 [`lsl-director-fight-video-prompt/SKILL.md`](lsl-director-fight-video-prompt/SKILL.md)。下面提到的“第几节”都指这个文件里的章节。

## 它解决什么问题

让语言模型写打斗提示词、再拿去生成视频，出来的毛病很固定，而且大多能在文字里找到成因：

| 生成出来的样子 | 文字里的成因 |
|---|---|
| 两个人贴在一起晃，看不出招 | 用了“交击三下”“激烈交手”这类概括词，一次接触只写了一下 |
| 碰一下，停下来说两句，然后爆炸 | 分开写成了停顿，台词写成“停下来说” |
| 手一挥对面就炸 | 法术跳过了成形和传导 |
| 命中像一阵风 | 只写了火花和衣袖，没写哪样东西被打坏 |
| 身后拖着一条光带 | 把残影写成了人物自带的尾巴 |
| 整段一个机位，看人闪来闪去 | 没排运镜，每一下没换角度 |
| 高潮看不清，拉远以后两个人停着 | 没写连切，没写拉远以后能量还在喷 |
| 下一段接不上 | 收在“画面结束”或对视喘气的空拍上 |

本 skill 把这些成因写成写稿时照着做、交稿前能在稿子上数出来的规则。完整的对照表在第十七节，共 31 行。

方法的来源是对一条豆包打斗提示词迭代链的复盘（人对模型的 17 轮纠正，加一份提示词模板）。在这个基础上补了四块原来没有的东西：按类型分的特效底座、环境反应、镜头密度与切换、爽点设计。

## 在流水线里的位置

```
剧本 → lsl-core-story-prompt（集核心、段核心、四张表）
     → director-video-prompt（导演母版、分段投喂版）
          └ 其中的打斗段 → 本 skill（一段一条全量提示词）
     → 即梦 Seedance 生成
```

没有上游两个 skill 也能单独用：直接给它一段剧情和要求就行。

## 交付什么

每次交付三样，分开放：

| 交付物 | 给谁 | 内容 |
|---|---|---|
| 工作稿 | 人 | 类型判定一句、打斗档案、回合表。用来审戏和排戏，不喂模型 |
| **全量提示词** | 视频模型 | 一段戏一条，整段复制粘贴就能生成，里面没有任何给人看的说明 |
| 说明 | 人 | 在你的想法上加的设计（每条可删）、模块取舍、下一步 |

### 全量提示词的固定模板

两行加十块，顺序不变：

```
上传顺序：@图片1 = 名字（管什么）；@图片2 = 名字；……

【全程无背景音乐，只有同期声】

【影像规格与质感】
16:9，15秒，N个镜头，……

【光影与色彩】
……

【场景环境】
……

【人物设定】
甲，外貌参考@图片1（样子以这张图为准）：……
乙，外貌参考@图片2（样子以这张图为准）：……

【特效设定】
……

【环境反应设定】
……

【声音设计】
……

【运镜设计】
总规则两三句。
1. 镜头1（0–2秒）：……
2. 镜头2（2–5秒）：……

【完整动作流程】

[0-2秒] 镜头1｜看得见的标题
承接：……
这一镜的正文，一段。
声音：……

[2-5秒] 镜头2｜看得见的标题
承接：……
这一镜的正文，一段。
声音：……

保持：……
```

| 块 | 写什么 |
|---|---|
| 上传顺序行 | 本段实际要传的参考图，按 @图片1、2…… 排。没有参考图就整行删掉 |
| 配乐声明行 | 有没有背景音乐 |
| 影像规格与质感 | 画幅、秒数、镜头数，类型的一句话，质感，焦段分工，节奏走向 |
| 光影与色彩 | 主光方向，第二光源，两方各自的颜色和排除色，环境底色，点缀 |
| 场景环境 | 地点，主要环境体占画面多少，这一段依次经过的地方，远处参照物，群像 |
| 人物设定 | 每人一段：外观、兵器、打法、高速移动时的痕迹、状态变化、台词原文 |
| 特效设定 | 兵器相撞的通用效果；每种法术从起手到残留；相克相撞的结果；终结一击 |
| 环境反应设定 | 由轻到重会被改变的东西各落在哪一镜；先后、方向、不遮挡三条规矩 |
| 声音设计 | 声音分几层，台词怎么说，全段最静和最响的一下在哪 |
| 运镜设计 | 总规则两三句，每镜一行机位和运动 |
| 完整动作流程 | 逐镜四样：镜头行、“承接：”、正文、“声音：”。从第一镜连着写到最后一镜 |
| 保持 | 整段都成立的状态：人数、颜色、伤和损耗、环境改变留到哪、没有文字 |

三条规矩让它“粘贴即用”：提示词里只有画面和声音，不出现表格、规则编号和工作词；样子写在设定块，事情写在动作流程；一条只管一段，一场打斗分几段就写几条，每条自足。详见第十三节。

## 方法一览

### 先判类型，再定特效底座

判定只看剧本里出现了什么描写。描写越少越往写实靠：没写发光就不发光，没写飞就不飞。一段里不换底座。

| 剧本里有 | 类型 | 底座 |
|---|---|---|
| 只有拳脚、兵器、枪械、车辆、爆炸 | 真人写实 | 一切按牛顿物理，没有发光，人被打飞不超过两三米 |
| 内力、轻功、剑气、掌风 | 武侠 | 力看不见，只能靠身体和环境看见：衣袂、落叶、尘、水面、烛火 |
| 法术、法器、灵力、御剑、五行、化形 | 玄幻 / 仙侠 | 能量可见，有来源、属性、消耗、相克；环境被大面积改写 |
| 魔法、符文、法阵、异能、魔物 | 奇幻（含都市、超英） | 元素化、符号化的魔法视觉；城市和人仍按真人反应 |
| 机甲、外骨骼、能量武器、变异体 | 科幻 / 末日 | 能量按奇幻写，环境和人体按真人写 |

四类底座在力从哪来、怎么看见力、出招过程、命中效果、颜色与光、环境反应、声音、摄影质感、禁忌上的差别，见第三节的对照表。

### 核心规则

| 规则 | 一句话 | 章节 |
|---|---|---|
| 骨架 | 段 → 回合（2–4 个，每回合换一个位置）→ 接触 → 交手（一次接触 3–6 下，招式各不同） | 六 |
| 分开后瞬合 | 分开不是停顿，退势未止就折返；写起止位置，不写“瞬移” | 六 |
| 串行对撞 | 九条对九条写成一条接一条地撞，每一对有自己的爆点 | 六 |
| 特效五段 | 起手、成形、传导、命中、残留；相克和消耗写成看得见的结果 | 3.3 |
| 力的四样 | 每次命中写接触点、被击者的身体、环境反馈、画面响应，至少三样 | 七 |
| 因果写法 | 残影、拖尾、劲风是速度的结果，不是人物自带的装饰 | 七 |
| 环境反应 | 近先远后、方向一致、改变了就留着、由轻到重分级；每镜至少两样环境在动 | 八 |
| 群像三圈 | 近、中、远三圈依次反应，不同时；具体到两三个人 | 8.3 |
| 镜头密度 | 15 秒 11–16 个视角、6–9 个镜头行；开局慢、中段密、高潮连切、收束一个长镜 | 9.1 |
| 每击换角度 | 连续两下不从同一个角度看；贴身和拉远至少交替两次 | 9.2、9.3 |
| 切点 | 每镜的“承接：”要答得出接的是上一镜的什么；切在出手前半拍 | 9.6 |
| 轴线 | 每回合一个复位镜，重新立住谁左谁右 | 9.7 |
| 爽点 | 压了再放；主爽点配连切、最重的环境反馈、骤静之后的爆 | 十 |
| 对白与代价 | 台词压在动作上，词句不改；每回合一处看得见的代价 | 十一 |
| 收束 | 拉远以后能量不散；收幅写清位置、姿态、能量、环境，留给下一段接 | 十二 |

交稿前有 22 条自检（第十六节），生成以后有诊断速查表（第十七节）。

## 怎么用

把这一段打斗的材料给它。缺的东西它会提案并标出来，只有“谁赢”和“台词归属”不明才会问。

| 要给的 | 说明 |
|---|---|
| 谁对谁、结果 | 谁赢谁输，或者打成什么局面停 |
| 每人能用什么 | 剧本给的武器、法术、装备 |
| 台词 | 原文、谁说、大概哪个时刻。它不改词句，只定压在哪一拍 |
| 代价 | 打完谁身上多了什么。没给就按每回合一处可见痕迹写 |
| 位移 | 从哪打到哪 |
| 规格 | 单段时长、画幅、目标模型、参考图和上传顺序；平台有字数上限也告诉它 |
| 剧本原话 | 和这段打斗有关的所有描写，哪怕只有半句。类型判定和环境反应靠它 |

一个可以直接发的起手指令：

```
/lsl-director-fight-video-prompt
项目：共工怒撞不周山 · 宣传片，第 1 段。
目标：即梦 Seedance 2.5，16:9，单段 ≤15 秒，图片写 @图片N（@图片1 = 祝融；@图片2 = 共工）。
剧情：开场祝融和共工已经在贯穿云海的水火龙卷风暴顶端交手，边打边飞，从风暴顶打到外围再打进风暴内部。祝融用赤焰长戟，放九条火龙；共工用玄冰长枪，放九条水龙。祝融在交手中说“今日你们注定要失败”，共工说“海天之上，我也一样压你”。这一段打成平手，但祝融占上风。
代价：共工左臂被火燎伤；祝融火色因为连放九条火龙暗了一档。
画风：国风神话大片，真人电影质感，胶片颗粒；无背景音乐，只有同期声。
环境：风暴几乎占满画面、顶端出框；雷云、闪电参与；云面可被推平、云壁可被撕开；点缀只要一两种暖色，不要发光植物。
本次重点：每次接触要是连击簇，分开后瞬合；九条龙一条接一条撞；高潮连切；收束留接口给第 2 段。
```

它按七步做：判类型 → 填打斗档案 → 排回合表 → 写全量提示词 → 自检 → 交付 → 生成后反馈。回复的顺序是：工作稿、全量提示词（单独一个代码框或文件）、在你的想法上加的设计、模块取舍、下一步。

生成以后，把看到的毛病告诉它。它先把现象归到文字上的成因再改，改一类问题会查全段。

## 示例

[`examples/示例_全量提示词_祝融对共工_15秒.txt`](examples/示例_全量提示词_祝融对共工_15秒.txt) 是上面那条起手指令对应的成品：玄幻空战，15 秒，8 个镜头，约五千五百字，文件里只有提示词，可以整段粘贴生成。SKILL.md 第十五节里是同一条。

| 秒 | 镜头 | 干什么 |
|---|---|---|
| 0–1 | 风暴顶的两点光 | 俯拍全景立住空间 |
| 1–3 | 云面上的四下 | 一次接触四下，各换一个角度 |
| 3–6 | 折返，祝融的一句话 | 分开后瞬合，台词压在兵器相抵上 |
| 6–8 | 挑飞，九条火龙 | 跟着被挑飞的人后退 |
| 8–10 | 九对龙，共工的一句话 | 反打，九对龙一对接一对地撞 |
| 10–11 | 穿进风暴 | 贴背跟飞，最后半拍骤静 |
| 11–13 | 对撞，四个角度 | 高潮，半秒一切 |
| 13–15 | 风暴被撕开 | 远景两秒不切，能量还在喷 |

其中一镜的样子：

```
[1-3秒] 镜头2｜云面上的四下
承接：祝融自右上俯冲，共工自左下迎上，相距几丈。
机位贴在共工背后半米、略低，20mm：他的左肩和枪杆占画面左下近一半，祝融带着火色残影从上方压下来，转眼冲到眼前。第一下，戟自上而下劈，共工横枪硬接，火星迸开，画面微颤一下随即稳住，他脚下的云面往下一沉。第二下，共工枪杆一斜卸开，戟刃压着枪身滑到枪缨，火星顺着接触的那条线蹿；他借力翻身绕向祝融侧后，机位跟着转了半圈，背景里云壁和闪电横着流过。第三下，机位已到祝融侧面、两人一左一右交错：共工回枪刺他后心，祝融不回头，戟尾向后一撩磕开枪尖，两人错身而过，肩与肩之间留着一拳的空隙。第四下，祝融拧腰回扫，机位顺着戟锋甩过去、停在共工身上：他后仰让过戟刃，戟刃上的火却擦过他的左小臂，甲片被燎出一道焦痕、冒起细烟；戟锋带起的劲风把他身后一大片云面推平，平下去的云往外跑出十几丈才停——错身的去势把两人甩开三十丈，共工后仰着往画面左侧退，祝融在右侧刚收住戟。
声音：一声金属硬接的脆响，一长串刮响，枪尖被磕开的清响，戟破风的低吼；云面被推平的一声闷响；共工短促的吸气声。
```

这条示例是按规则写出来的样稿，还没有生成过。

## 和 director-video-prompt 一起用

全量提示词的首行、镜头行、“承接：”“声音：”“保持：”，用的就是 director-video-prompt 0.9.6 投喂版的行格式。所以同一条稿子可以原样存成它项目里的段文件（如 `01A.txt`），不用另写第二个版本。上面那条示例放进它的测试项目跑过结构自检，投喂版那一组检查全部通过。

放进导演 skill 的项目时，上传顺序里的名字改用项目资产库里的名字；工作稿放进母版里的加粗块，不开新小节。项目要无标题的排法时，去掉【】标题行即可，内容不删。详见 13.5。

## 篇幅

15 秒一段的全量提示词大约四千到五千五百字。超过六千字，先查是不是有一件事写了两遍。

平台到底吃得下多少，目前没有可靠的官方数字。2026-11-11 查到的是：Seedance 2.0 的一份第三方接口文档写“建议中文不超过 500 字，提示词最大 10000 tokens”，它不是官方文档，不是即梦网页端，也不是 2.5；Seedance 2.5 的官方手册没有写提示词上限。所以“粘得进去”不等于“模型逐条照做”，长稿的效果要靠生成来验证。

需要短版时按固定顺序压：先删【运镜设计】里每镜那几行，再把【声音设计】并进每镜的“声音：”，再压【环境反应设定】【特效设定】，再把【光影与色彩】并进【影像规格与质感】，最后压“承接：”。【人物设定】、动作流程的正文和“保持：”不压。详见 13.4。

## 测试状态与并入路线

三类案例都还没跑：

| 案例 | 类型 | 状态 |
|---|---|---|
| 祝融对共工，15 秒一段 | 玄幻空战 | 样稿已写（即本仓库示例），未生成 |
| 《诸神拯救计划》14K 重写，和上一版并排对照 | 都市奇幻、人对巨物 | 未开始 |
| 客栈回廊一对多，或《末日神装》一段装备战 | 真人 / 武侠近战 | 未开始 |

每个案例的流程：出工作稿和全量提示词 → 先用分镜总览图审 → 生成 → 按诊断表归因 → 记台账。第一个案例顺带测篇幅：同一段出全量版和两千字左右的短版，各生成一次，看哪些块模型真的在照做。

建议的达标标准：三类案例至少两类生成后认可；22 条自检全过；全量提示词原样存成段文件能过导演 skill 的结构自检。

达标以后并入 director-video-prompt，成为它的“打斗段落”一节，导演 skill 升到 0.10.0；并入前导演 skill 不改。怎么并写在第十八节。
